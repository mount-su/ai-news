# 大模型厂商官方博客与 Reddit 线索扩源设计

## 背景与目标

当前启用的数据源只有 OpenAI、Google AI、DeepMind 和 Hugging Face 的官方订阅，中文大模型厂商覆盖不足，也缺少能发现新产品和高质量应用案例的社区线索。此次扩源以厂商官方内容为主体，并增加一个严格受限的 Reddit 社区 RSS 线索源；现有 36 小时时间窗、历史去重、编辑过滤和 LLM 精选流程保持不变。

目标如下：

1. 新增 10 个可自动验证的厂商官方来源，其中 7 个来自中国厂商。
2. 官方 RSS/Atom 优先；没有订阅源时使用显式、独立的官网页面适配器。
3. 新增一个无需密钥的 Reddit RSS 线索源，只覆盖大模型、AI 应用和 AI 产品赛道，并将最终链接指向经过验证的外部原文。
4. 单个来源改版、超时、限流或拦截时只标记该来源失败，不中断其他来源和整条日报流水线。
5. 厂商博客和 Reddit 线索仍需通过现有质量口径；扩源不等于放宽收录标准。

## Reddit 社区 RSS 线索源

### 角色与社区范围

Reddit 只作为社区发现渠道，不作为事实背书。首批社区固定为：

- 大模型：`r/LocalLLaMA`、`r/OpenAI`、`r/ClaudeAI`、`r/GeminiAI`；
- AI 应用与产品：`r/artificial`、`r/ChatGPT`、`r/aiagents`、`r/perplexity_ai`；
- 生成式 AI 产品：`r/StableDiffusion`。

不采集 `r/MachineLearning`、`r/singularity`、综合科技社区或 Reddit 全站搜索，避免论文研究、未来猜测和泛科技内容扩大噪音。

### 订阅方式与限流

采集器通过 Reddit 官方多社区 Atom 输出读取两条固定订阅：

- 九个社区合并后的 `new/.rss?limit=100`；
- 九个社区合并后的 `top/.rss?sort=top&t=day&limit=100`。

两次请求必须串行执行并至少间隔 20 秒，禁止为九个社区分别发请求。实时验证表明，合并订阅可一次返回 100 条 Atom 记录，但匿名请求在一次访问后可能出现约 15 秒的速率恢复窗口。

该方案不需要 `REDDIT_CLIENT_ID`、`REDDIT_CLIENT_SECRET`、登录 Cookie 或 Reddit 账号。收到 `403` 或重试后的 `429` 时，将 Reddit 标记为单源失败，不改用 HTML 抓取、第三方代理或登录态绕过。

### Reddit 条目转换

Reddit Atom 条目的主链接指向讨论页，正文中的 `[link]` 才可能是外部原文。专用解析器按以下顺序处理：

1. 读取社区名、Reddit 帖子 ID、标题、发布时间和正文中的 `[link]` 目标；
2. 拒绝自帖、讨论页、图片/视频直链、Reddit 媒体域名、短链接、求助、传闻、Meme 和自我推广；
3. 标题和外部页面元数据必须明确命中“大模型”“AI 应用”或“AI 产品”主题；
4. 外部目标必须属于已启用厂商官方域名，或显式可信域名列表；首批可信媒体域名为 `reuters.com`、`apnews.com`、`theverge.com`、`arstechnica.com`、`techcrunch.com` 和 `wired.com`；
5. 受限读取外部页面的标题、摘要和明确发布日期；无可验证发布日期、无法读取或跳转到非允许域名的条目直接拒绝；
6. 使用外部原文 URL 和原文发布日期生成 `RawItem`，来源名记录为 `Reddit · r/<community>`，权重固定为 5，`official` 固定为 `false`；
7. `new` 与 `top/day` 中指向同一原文的记录按规范 URL 合并，再与厂商官方来源做全局去重；官方来源的高权重使其在重复时胜出。

RSS 不提供稳定的赞数、赞同比和评论数，因此这些指标不进入排序，也不从页面补抓。`top/day` 只提供 Reddit 自身排序后的补充候选；最终质量仍由确定性过滤和 LLM 主编判断。

系统不保存 Reddit 用户名、帖子正文、评论、图片或投票数据。报告只保留社区名称、外部原文信息和现有候选追溯字段。

## 采集架构

### 配置模型

`SourceSpec.kind` 新增 `official_page` 和 `reddit_rss`。`official_page` 必须同时配置 HTTPS `url` 和 `adapter`；`adapter` 必须存在于程序内的允许列表，未知值在读取配置时直接报错。`reddit_rss` 必须配置非空、无重复且满足 Reddit 社区名称格式的 `communities`，不接受自定义 URL、仓库或页面适配器。`feed`、`arxiv` 和现有历史配置保持兼容。

页面适配器名称与厂商一一对应，例如 `anthropic_news`、`meta_ai_blog` 和 `deepseek_news`。配置只决定使用哪个已审查适配器，不能从 YAML 注入 CSS 选择器、正则表达式或任意请求地址。

### 适配器边界

新增统一的 `official_page` 采集入口和适配器注册表。每个厂商适配器只负责：

1. 从配置中的官方索引页发现文章；
2. 提取标题、规范链接、明确发布日期和可用摘要；
3. 对综合新闻中心执行已配置的品牌关键词预筛；
4. 返回统一的 `RawItem`，交回现有流水线处理。

适配器只能请求配置入口的同一官方站点，或该适配器代码中明确允许的官方子域名。只接受 HTTPS 文章链接。每个来源最多读取索引中的 30 条记录；只有索引摘要不足时才读取详情页，每次运行最多补充 8 个详情页，正文摘要沿用 4,000 字符上限。

发布日期必须来自页面明确展示的日期或结构化元数据。适配器不得把抓取时间、站点地图更新时间或 HTTP 响应时间冒充文章发布时间。没有可验证发布日期的条目直接丢弃；只有日期没有时区时，按该来源明确配置的发布地区时区解释，再统一转换为 UTC。

### 数据流

1. 读取并校验来源配置。
2. 按现有并发上限运行 `feed`、`official_page` 和单个 `reddit_rss` 来源；Reddit 内部两次请求保持串行。
3. 页面适配器和 Reddit 专用解析器生成标准 `RawItem`；来源结果写入现有 `SourceRun` 健康记录。
4. 全部条目进入现有 36 小时时间窗、URL/标题去重、历史去重和来源平衡排序。
5. 通过确定性编辑过滤后，由现有 LLM 主编统一整理和精选。
6. 站点继续只展示精选日报，不新增原始抓取列表或数据源目录页面。

## 内容口径

扩源后允许进入候选池的内容包括：

- 重要模型或产品正式发布；
- 面向用户的重大能力、价格、可用地区或使用方式变化；
- 有明确事实和实际影响的高质量技术文章；
- 重要商业合作、平台政策和安全治理变化。
- Reddit 发现且能回溯到可信外部原文的高质量产品、应用或技术报道。

以下内容继续排除：

- 论文解读、底层科研细节、训练方法和单纯基准成绩；
- SDK/API 小改动、接口参数说明、补丁版本和普通故障修复；
- 没有具体变化的品牌宣传、活动预告和观点稿；
- 综合新闻中心里的非 AI 企业新闻；
- 只有标题、没有明确发布日期或无法追溯可信原文的内容。
- Reddit 自帖、评论、截图、图片作品、求助、传闻、Meme、投票和自我推广。

## 失败与安全策略

- 网络超时、非成功响应、响应过大、非法跳转继续复用现有受限 HTTP 客户端策略。
- 页面结构完全不匹配、出现登录/验证码/机器人挑战页时，适配器抛出安全的结构错误，`SourceRun` 标记失败并返回零条；不得把“页面改版”伪装成正常零更新。
- 页面结构有效但 36 小时内没有新文章属于正常情况，不视为来源失败。
- Reddit 的两条合并订阅按速率窗口串行读取；`403` 或重试后的 `429` 只使 Reddit 来源失败，不触发密钥或抓取降级。
- 单个来源失败不得使其他来源失败；只有现有发布门槛或 LLM 阶段失败时才阻止新日报覆盖旧日报。
- 日志只记录来源 ID、状态、条数、耗时和安全错误码，不记录正文、响应头、令牌或完整异常对象。
- 不绕过登录、验证码、robots 限制，不使用浏览器模拟，也不接入第三方转发服务。

## 测试与验收

### 自动化测试

- 配置测试覆盖 `official_page` 必须具有 HTTPS URL、已知适配器，以及其他来源类型不接受无关适配器字段。
- 每个厂商适配器使用固定 HTML/Markdown 样本验证标题、官方链接、日期、时区、摘要和品牌预筛。
- Reddit 测试使用固定 Atom 样本验证社区白名单、`new`/`top` 合并、外部 `[link]` 提取、主题过滤、可信域名、原文日期和跨来源去重。
- Reddit 负面样本覆盖自帖、讨论链接、图片/视频、短链接、未知域名、求助、传闻、Meme、自我推广、缺失原文日期和超量响应。
- 网络测试验证 Reddit 两次订阅请求不会并发，间隔不少于 20 秒；订阅响应 `403` 或重试后仍为 `429` 时标记 Reddit 来源失败，单条外部原文读取失败时只丢弃该条目。
- 通用安全样本验证非 HTTPS 链接、非允许域名链接、缺失日期、挑战页、结构改版和超量详情请求被拒绝或受限。
- 流水线测试验证 `official_page` 和 `reddit_rss` 正确分派；其中一个来源失败时，其他来源仍完成并保留各自 `SourceRun` 状态。
- 回归测试验证现有 feed、时间窗、去重、编辑过滤、LLM 精选和静态站点构建行为不变。

### 合并前实时检查

- 从执行环境实际访问 10 个新增官方入口，确认最终地址仍为允许的官方域名。
- 每个来源必须能解析出至少一条带明确发布日期的历史记录；不能解析的来源不得以启用状态合并。
- 实际访问 Reddit 合并 `new` 和 `top/day` 订阅，确认 GitHub Actions 环境能获得 Atom 响应，并至少解析出一条符合外链结构的候选；不满足时 Reddit 保持禁用，不影响 10 个厂商来源上线。
- 运行完整测试、覆盖率、Ruff、Secret 扫描、静态构建和工作流检查。

### 生产验收

- 合并后手动触发一次 GitHub Actions，并确认采集工作流和 Pages 部署成功。
- 工作流日志中 10 个新增厂商来源和 Reddit 来源均出现独立健康结果；当天没有新文章可以为零条，但不得因结构不匹配而静默为零。
- 检查正式网站最新一期：来源链接只指向厂商官方域名或 Reddit 允许的可信外部域名，内容仍符合精炼质量口径，桌面和移动页面没有因扩源发生样式回归。

## 非目标

- 不把第三方媒体、社交账号或搜索 API 配置成独立定时来源；只有 Reddit RSS 中指向显式可信域名的外部原文可以进入候选。
- 不恢复 GitHub Release 数据源或 arXiv 数据源。
- 不调整页面视觉设计、日报数量上限、栏目体系和 LLM 接口配置。
- 不为暂缓厂商编写未经实时验证的通用抓取规则。
- 不使用 Reddit OAuth、网页抓取、评论、用户画像或投票指标。
