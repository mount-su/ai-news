# AI 情报日报 V2 整体改造规格

## 1. 背景与问题证据

本次改造同时解决界面、功能、来源供给和编辑质量问题，不能只做视觉换肤。

以 `origin/main` 的 `357707e` 和 2026-08-30 线上日报为基准：

- 20 个配置来源都被页面显示为“正常”，但 Reddit 返回 0 条且耗时 62.8 秒，12 个来源在近 120 小时内没有新内容；当前状态只证明请求未抛错，不代表来源新鲜或有贡献。
- 2475 条原始记录只有 48 条进入 120 小时时间窗，历史去重后 39 条，规则过滤后 30 条；其中 Product Hunt 占 25 条、OpenAI 4 条、Google 1 条。
- 单源限额后只剩 8 条候选，最终 5 条中 OpenAI 3 条、Product Hunt 2 条；两条 Product Hunt 内容的营销风险为高，其中一条重要度仅 4。
- 编辑规则把 `category_hint` 拼进内容判断。DeepMind 的默认分类是“论文研究”，因此 Gemini 产品更新会被“论文”关键词误杀；英文研究内容反而可能通过。
- 首页第一条正文桌面和手机都要滚动约 640px 才出现；来源状态重复两次。大模型分类页完整铺开 20 条长文，手机页面接近 8000px。
- 已生成 `search.json`，但没有搜索界面；日页没有前后期导航，导航没有当前页状态，首页和日页的 CSS 编号均显示 `00`。
- push 到 `main` 时 build 成功而 deploy 被跳过，README 所述的自动部署行为与实际工作流不一致。

## 2. 已确认决策

1. 保留 Python 3.12、Jinja、静态文件、GitHub Actions 和 GitHub Pages，不迁移到前端框架，不增加数据库或服务端。
2. 视觉采用成熟中文财经日报方向：暖白纸面、深墨正文、克制红色强调、正式报头和清晰主次关系。去掉深色科技面板、圆角卡片、渐变、概念标签和 demo 式装饰。
3. 日报正常目标为 3–7 条。模型可以少选，不用 Product Hunt、Reddit 或高营销风险内容凑数。
4. 功能范围包括全文搜索、频道/来源/日期筛选、日页前后期导航、来源新鲜度与贡献状态、RSS、SEO、分享元信息和自定义 404。
5. 新规则上线后，按日期顺序重新生成最近 14 天；Git 历史保留旧版本，可恢复。
6. 数据源按“官方一手源、可信媒体、社区线索”三层管理。社区线索不能未经验证直接成为正式日报事实。
7. 不新增付费搜索 API，不新增密钥，不进行通用网页抓取。新增来源必须是固定允许列表中的 HTTPS Feed 或专用官网适配器。

## 3. 方案选择

### 方案 A：局部修补

只调整 CSS、增加搜索框并修改少量提示词。交付快，但来源健康失真、规则误杀、Product Hunt 补位和历史内容污染仍会反复出现，因此不采用。

### 方案 B：静态日报 V2

保留现有静态架构，成体系地升级站点呈现、搜索功能、流水线诊断、来源分层、质量门槛和回填语义。它能在不增加运维面的前提下解决当前主要问题，采用该方案。

### 方案 C：前端框架迁移

迁移到 React/Next 等框架后再重做数据层。扩展空间更大，但对当前数据量和 GitHub Pages 场景明显过重，会引入构建、路由和依赖维护成本，因此不采用。

## 4. 信息架构与视觉设计

### 4.1 全局报头

- 使用居中的“AI 情报日报”刊名，左侧显示日期和期数，右侧显示“有新内容的来源数”和截止时间。
- 状态只展示一次，不再使用“20/20 正常”这种请求层指标。
- 一级导航固定为：今日、大模型、Agent、AI 产品、开源生态、行业政策、归档、搜索。
- `Coding Agent` 在展示和搜索层统一归入 `Agent`；历史 JSON 仍兼容旧枚举。
- `论文研究` 不再出现在导航。历史论文保留在 Git 和旧日报页面中，但不进入当前分类聚合和默认搜索结果。
- 当前页面使用 `aria-current="page"` 和可见下划线标识。

### 4.2 首页

- 首屏目标：桌面第一条正文顶部不低于 250px、不高于 430px；手机不高于 500px。
- 最新日报按重要度和发布时间生成一条主稿、最多三条“今日速览”，其余放入紧凑要闻列表。
- 主稿完整展示标题、摘要、影响、来源、发布时间、证据类型和营销风险提示。
- 速览与其余要闻只展示标题、单段结论、来源和发布时间；避免重复铺开“变化/影响”两大段。
- 标题可点击原始来源，同时提供稳定的当日文章锚点供搜索结果和分享使用。
- 明确区分“发布时间”和“收录日期”。超过 48 小时但仍在 120 小时补充窗的内容显示“补充收录”和相对天数。

### 4.3 分类页与归档

- 分类页默认按发布时间倒序，使用紧凑时间线，每页 20 条；不无限增长成超长页面。
- 分类列表只展示摘要，影响内容通过原文或当日日报锚点查看，不在列表全部展开。
- 分页生成稳定静态路径，第一页保留现有分类 URL，后续页为 `page/2/`、`page/3/`。
- 归档在手机端仍显示收录数和候选数；缺失日期显示“未生成/无合格内容”说明，而不是静默跳过。
- 日页提供上一期、下一期和返回归档三个导航入口。
- 新增 `/sources/` 来源状态页，从最新运行诊断生成；它不进入一级频道导航，由报头状态和页脚链接进入。

### 4.4 响应式与可访问性

- 820px 以下采用单列；频道导航可横向滚动，并用边缘渐隐和“更多频道”提示表达可滚动性。
- 正文辅助信息字号不低于 12px，正文不低于 15px，触控目标不低于 44px。
- 保留跳过链接、键盘焦点、语义标题结构、`prefers-reduced-motion` 和足够颜色对比度。
- 不依赖远程字体；使用系统中文宋体与黑体回退，避免页面阻塞和字体隐私请求。

## 5. 搜索与阅读功能

### 5.1 搜索索引

- 构建公开的精简 `search.json`，只包含最近 180 天的公开字段：ID、标题、摘要、影响、标签、展示分类、来源、发布时间、收录日期、官方标记、营销风险和带文章 fragment 的日页 URL。
- 索引默认按发布时间倒序，不沿用重要度优先；展示分类中合并 Agent/Coding Agent，排除论文研究。
- 输出稳定、可复现且经过 HTML 转义；不包含抓取原文、私有配置或模型提示词。

### 5.2 搜索页面

- 新增 `/search/` 静态页面，输入后懒加载 `search.json`，不在所有页面启动时下载索引。
- 支持标题、摘要、影响、来源和标签的中文/英文大小写无关匹配。
- 支持频道、来源和日期范围筛选；默认最近 30 天、按时间倒序。
- 提供加载中、无结果、索引失败三种状态，并允许用户清空筛选。
- 搜索结果链接到 `days/YYYY-MM-DD/#item-<id>-<date>`，页面加载后可见目标文章。
- 全站导航提供搜索入口；桌面支持 `/` 聚焦搜索，手机不劫持输入法按键。

### 5.3 订阅、SEO 与分享

- 生成 `feed.xml`，包含最近 30 天正式入选条目，链接回当日日报锚点并保留原始来源链接。
- 生成 `sitemap.xml`、`robots.txt`、`404.html` 和本地图标。
- 每页提供 description、canonical、Open Graph、Twitter Card 和正确标题；站点绝对地址固定为 `https://mount-su.github.io/ai-news/`。
- 404 页面提供返回首页、搜索和归档入口，不依赖 JavaScript。

## 6. 来源分层与供给策略

### 6.1 来源角色

`SourceSpec` 增加兼容旧配置的 `role`：

- `primary`：官方厂商、产品、平台或项目一手源，可作为事实依据。
- `trusted_media`：经过允许列表验证的专业媒体，可作为报道依据，页面明确显示媒体来源。
- `discovery`：Product Hunt、Reddit 等社区或榜单，只提供线索。

未配置 `role` 的现有官方源默认 `primary`，其他源默认 `trusted_media`；Product Hunt 和 Reddit 显式设为 `discovery`。

### 6.2 来源调整

- 保留现有官方国际与中国厂商来源，但来源健康改为检查新鲜度，不能用陈旧历史记录证明“正常”。
- 新增四个已验证的直接 AI Feed 作为可信媒体：TechCrunch AI、VentureBeat AI、The Verge AI、The Decoder。
- 不采用当前会跳转为 HTML、返回 403/451 或没有真实 Feed 的机器之心、量子位、36Kr、InfoQ 入口。
- Sourcegraph、Cursor、Ollama 与 GitHub Blog 保留为对应 Agent、开源和工具频道的一手源。
- arXiv 继续禁用；论文研究不作为当前日报供给目标。

### 6.3 供给验收

- 每周统计每个来源的最后新内容时间、近 7 天新内容数、合格候选数和最终入选数。
- 每个主频道至少有两个独立、近期有内容的来源；未达到时显示供给警告，但不靠低质来源凑数。
- `source-health` 每天定时运行并可手动触发；请求失败、空结果、最后内容超出阈值分别记录，不能合并成一个布尔值。

## 7. 编辑质量与流水线

### 7.1 分阶段诊断

每个 `SourceRun` 继续使用现有 `success` 表示请求与解析是否成功，并新增以下可空诊断字段：

- `item_count`：解析出的历史记录数；
- `recent_count`：进入 120 小时窗口的记录数；
- `new_count`：排除 30 天历史 URL 后的记录数；
- `eligible_count`：确定性质量规则通过数；
- `candidate_count`：进入模型的候选数；
- `selected_count`：最终入选数；
- `latest_published_at`：该源最新可解析发布日期。

历史报告缺少新增字段时使用 `null`，页面显示“历史数据不可用”，不能伪造为 0。

每次生成另写一份不含凭证的运行记录到 `data/runs/YYYY/MM/YYYY-MM-DD.json`，状态只能是 `published`、`no_eligible_content` 或 `failed_before_publish`。记录包含日期、截止时间、逐源诊断和安全错误码，不包含外部全文、模型原始响应或异常堆栈。正式日报仍写入现有 `data/YYYY/MM/YYYY-MM-DD.json`；0 条时只更新运行记录，不覆盖首页所用的最后一期日报。归档结合日报与运行记录解释日期缺口。

### 7.2 编辑过滤

- 学术、低质技术和公司新闻的内容判断只使用标题与摘要，不把 `source_name` 或 `category_hint` 当作正文关键词。
- 增加英文研究负例：paper、preprint、randomized controlled trial、study、evaluation 等在缺少产品可用性、价格、部署或政策影响时拒绝。
- 保留 DeepMind/Hugging Face 等来源中的产品、模型可用性、性能成本和重大开源发布。
- Product Hunt/Reddit 候选只能在解析到可信外部目标和足够正文时继续；`discovery` 来源且 `marketing_risk=high` 的分析结果直接从正式日报剔除。
- `is_official` 必须由来源配置决定，模型不得覆盖来源事实。

### 7.3 排序、去重与多样性

- 候选分数降低静态来源权重的支配程度，加入发布时间、摘要完整度、来源角色、官方属性和频道稀缺度。
- 120 小时时间窗保留，但 72–120 小时只作为补充，分数继续衰减，页面显式标龄。
- 同一 canonical URL 继续强去重；发现源能解析到官方 URL 时使用官方 URL，使其自然与一手源合并。
- 对标题执行产品名和事件词归一；跨来源重复时优先 `primary`，其次 `trusted_media`，最后 `discovery`。
- 最终单一来源最多 2 条。正常目标 3–7 条，不设“候选达到 5 就必须选 5 条”的硬门槛。
- 当高质量内容不足 3 条时按实际数量发布；0 条时保存可解释的“无合格内容”运行记录，不覆盖最后一期首页。

### 7.4 历史日期语义

- 今日生成的窗口截止时间为实际运行时间。
- 指定过去日期时，窗口截止时间固定为该日期 `23:59:59 Asia/Shanghai`，不能用当前时间内容写入过去日期。
- 最近 14 天重生成按日期从旧到新串行执行，确保 30 天历史去重只参考更早日期。

## 8. Actions、错误处理与安全

- 修复 push 到 `main` 时 `generate` 被跳过导致 deploy 连带跳过的问题；deploy 只依赖 build 的成功结果。
- 日常计划任务继续每天北京时间 08:17 运行。来源健康任务每日运行，日报任务不因单个非关键来源失败而整体中止。
- 生成、构建、校验或部署任一阶段失败时不替换线上最后成功版本。
- 搜索索引加载失败时显示本地错误态，首页、分类和归档仍可使用。
- 所有外部内容继续视为不可信输入，模板自动转义，URL 经过 HTTPS 和允许列表校验。
- 不读取、打印或测试 `LLM_API_KEY`；新增功能不需要新的 Secret。

## 9. 测试与验收

### 9.1 自动化

- 数据模型兼容旧报告和新诊断字段。
- 回归测试覆盖 DeepMind 产品正例、英文研究负例、分类词不误杀、社区高营销风险剔除、官方属性不可被模型篡改。
- 排序测试覆盖新鲜度、来源角色、摘要完整度、频道稀缺度和单源最多 2 条。
- 历史日期测试证明过去日期使用上海时区日末作为窗口截止。
- 站点测试覆盖首页主稿/速览/列表、连续编号、active nav、分类分页、前后期导航、搜索深链、来源状态、404、RSS、sitemap 和 metadata。
- JavaScript 测试覆盖搜索加载、关键词与筛选组合、空态、错误态和 URL fragment。
- workflow 测试证明 push 构建成功后 deploy 会执行。
- 完整运行 Ruff、pytest、Secret 扫描、离线站点构建与验证。

### 9.2 线上验收

- GitHub Actions CI、来源健康和 Daily AI news 全部成功。
- Pages 首页、五个频道、搜索、归档、日页、来源状态和 404 均返回正确页面。
- 桌面 1440×900 与手机 390×844 无横向溢出；首页正文进入首屏范围；搜索和筛选可实际使用。
- 页面显示“近期有内容的来源数”，不再把 Reddit 0 条显示为正常贡献。
- 最新日报不包含纯论文、低质小版本、无事实营销稿或未验证的高风险社区线索。
- 最近 14 天从旧到新重生成后，分类页来源分布不再被旧 arXiv 和单一厂商主导。
- 合并后手动触发一次完整日报部署，核对线上部署 SHA 包含 V2 合并提交。

## 10. 交付拆分

实施分为四个可独立验证但最终一起发布的阶段：

1. 修复部署、历史日期语义、编辑误杀、来源角色和分阶段诊断。
2. 新增可信媒体来源、来源新鲜度巡检、多样性与质量门槛。
3. 实现日报 V2 页面、搜索、分页、导航、来源状态、RSS、SEO 和 404。
4. 完整回归、合并部署、串行重生成最近 14 天并进行线上验收。

本次以完成四个阶段并通过线上验收为完成条件，不以“代码已提交”或“CI 通过”替代生产验证。
